# Wire-v1 golden vectors (RM-1330 / LIM-1446)

Golden JSON fixtures for the **canonical wire-v1 encoding** specified in
[`docs/wire-encoding.md`](../../docs/wire-encoding.md) and produced by
`encode_canonical_ipc_message` (`src/compatibility.rs`).

## Layout

- `manifest.json` — schema version, encoding profile, generator command, and
  for every fixture its file name, SHA-256 digest, `kind` (`positive`,
  `legacy`, `alias`, `normalization`, `negative`), `variant` (the
  `IpcMessage` variant a positive vector encodes), and `expect` (the decode
  expectation: `decode_ok`, `too_old`, `too_new`, `payload_error`,
  `json_error`).
- `*.json` — one envelope or legacy document per fixture. Positive files are
  byte-identical canonical encodes (compact, sorted keys, UTF-8, no trailing
  newline). Hand-maintained files may be pretty-printed.

## Kinds

- **`positive`** — generated by `encode_canonical_ipc_message` at wire
  version 1. Every current `IpcMessage` variant has at least one; the
  integration test fails on a missing variant. Do not hand-edit: regenerate.
- **`legacy`** — pre-envelope unversioned tagged JSON. Still accepted as
  legacy wire version 1 (`WireCompatibility::LEGACY_UNVERSIONED`).
- **`alias`** — the `TraceData.channel_id` field also accepts `neuron_id` on
  decode; this vector locks that alias.
- **`normalization`** — records the documented non-lossless decode:
  `ConfigValue::Integer` arrives as `ConfigValue::Float`, with f32 precision
  loss above 2^24 (`16777217` → `Float(16777216.0)`).
- **`negative`** — unsupported versions (`v0` too old, `v2` too new —
  rejected **before** payload interpretation), unknown variant, wrong
  tagging, malformed JSON, and schema-invalid payloads (out-of-range
  neuromodulator level, `valid_mask` length mismatch).

Never regenerate `legacy`, `alias`, `normalization`, or `negative` vectors
through the canonical encoder — it only emits current-version envelopes and
would silently drop the compatibility coverage they exist for.

## Regenerating

Positive-vector drift (encoder change or intentional fixture update) fails
`tests/wire_v1_vectors.rs`. Regenerate intentionally with:

```bash
REGENERATE_WIRE_V1=1 cargo test --locked --test wire_v1_vectors regenerate_fixtures
```

This rewrites the `positive` files from `encode_canonical_ipc_message` and
recomputes every SHA-256 in `manifest.json`. Hand-maintained fixture content
is never touched. Review the diff before committing — regeneration is the
only supported way to change canonical bytes.

## Verifying digests (any language)

```bash
python3 - <<'PY'
import hashlib, json, pathlib
root = pathlib.Path("test-vectors/wire-v1")
manifest = json.loads((root / "manifest.json").read_text())
for entry in manifest["fixtures"]:
    data = (root / entry["file"]).read_bytes()
    assert hashlib.sha256(data).hexdigest() == entry["sha256"], entry["name"]
print("ok", len(manifest["fixtures"]))
PY
```

## Cross-language reuse

The corpus is the conformance target for non-Rust consumers (LIM-1327:
Python and Julia readers of this golden corpus). A consumer should decode
each `decode_ok` fixture to the message shape implied by its `variant`, apply
the same version-before-payload ordering to `negative` fixtures, and treat
`manifest.json` digests as the integrity check. The normalized domain rules
(finite floats only, `Integer` → `Float`, signed zero preserved) are defined
in `docs/wire-encoding.md`, not re-specified here.

Repo-only: `test-vectors/` is outside the crates.io `include` allow-list;
the integration test loads files via `CARGO_MANIFEST_DIR`.
